# 文件自动分类工具 · 新手操作文档

本工具会把一个目录下的文件（如影视、文档等）按你定义的维度（系列 / 主演 / 主题等）自动归类到对应文件夹。

**最重要的安全设计：工具永远「先出报告、你人工检查后才移动文件」（`report` 只生成报告，`apply` 才移动），并且每次移动都会保存清单，可以随时一键还原。**

---

## 1. 环境准备

- **JDK 8**（或更高版本）
- **Maven 3.x**
- 能联网（首次构建需要下载 Maven 依赖）

检查是否已安装：

```bash
java -version
mvn -version
```

首次使用前，在项目根目录（`pom.xml` 所在目录）编译一次：

```bash
mvn -q compile
```

> 下文所有命令都在项目根目录执行，并以 `mvn exec:java` 方式运行。
> 你也可以先 `mvn package` 打包，再自行拼 classpath 用 `java -cp ... com.qian.categorize.Application` 运行。

### 命令的通用写法

```bash
mvn -q exec:java -Dexec.mainClass=com.qian.categorize.Application -Dexec.args="<子命令和参数>"
```

这条命令各部分的含义：

| 片段 | 含义 |
| --- | --- |
| `mvn` | 调用 Maven 来运行本项目（Maven 会自动用 `pom.xml` 里声明的依赖拼好 classpath，不用自己手动拼 jar 路径）。 |
| `-q` | quiet，安静模式：只打印程序自身的输出和错误，不刷 Maven 的下载/构建日志，报告更干净。不想要可去掉。 |
| `exec:java` | 调用 `exec-maven-plugin` 插件的 `java` 目标——作用是「在 Maven 进程里直接运行某个 Java 类的 `main` 方法」，而不是执行 compile/package 这样的构建阶段。**你之前报 `Unknown lifecycle phase "report ..."`，就是因为少了这一段，Maven 把 `report ...` 误当成了构建阶段。** |
| `-Dexec.mainClass=com.qian.categorize.Application` | `-D` 是给 Maven 传系统属性；这里告诉插件要运行哪个类（含 `main` 方法的入口类，即本项目的 `Application`）。 |
| `-Dexec.args="<子命令和参数>"` | 传给上面那个 Java 类 `main(String[] args)` 的命令行参数。引号里写的内容，会原样成为程序收到的参数。 |

**`-Dexec.args` 在哪里被用到**：它的值最终进入 `Application.main` 的 `args`，由 `cli/CommandLine.java` 解析——第一个词是子命令（`init`/`scan`/`report`/`apply`/`rollback`），后面是目录路径或报告/清单文件，以及可选的 `--config <文件>`、`--report <文件>`。也就是说，平时你想给工具传什么参数，全部写在 `-Dexec.args="..."` 的引号里即可，例如：

```bash
# 程序实际收到的 args = ["report", "/Users/you/Movies"]
mvn -q exec:java -Dexec.mainClass=com.qian.categorize.Application -Dexec.args="report /Users/you/Movies"

# args = ["report", "/Users/you/Movies", "--config", "/Users/you/categorize-config.json"]
mvn -q exec:java -Dexec.mainClass=com.qian.categorize.Application -Dexec.args="report /Users/you/Movies --config /Users/you/categorize-config.json"
```

> 提示：`exec:java` 默认在同一个 JVM 里运行，编译好的类来自 `target/classes`。改了代码后先执行一次 `mvn -q compile` 再运行，否则跑的还是旧代码。

为了少打字，建议先设一个别名（当前终端生效）：

```bash
alias categorize='mvn -q exec:java -Dexec.mainClass=com.qian.categorize.Application -Dexec.args'
```

设置后，命令可简写为：

```bash
categorize "report /Users/you/Movies"
```

别名末尾就是 `-Dexec.args`，所以 `categorize "..."` 引号里写的内容，等于完整命令中 `-Dexec.args="..."` 的值，会原样作为子命令和参数传给程序。

> 路径中含空格时，记得用引号包住。下文统一使用简写形式。

### 不设别名：直接用完整 mvn 命令

如果不想设置 `categorize` 别名（例如新开终端、别名失效），把下文每条 `categorize "..."` 替换成下面的完整写法即可——把引号里的子命令原样放到 `-Dexec.args=` 后面：

```bash
# 通用形式
mvn -q exec:java -Dexec.mainClass=com.qian.categorize.Application -Dexec.args="<子命令和参数>"
```

各命令的完整示例（以整理目录 `/Users/you/Movies` 为例）：

```bash
# 生成配置骨架
mvn -q exec:java -Dexec.mainClass=com.qian.categorize.Application -Dexec.args="init ."

# 试扫描
mvn -q exec:java -Dexec.mainClass=com.qian.categorize.Application -Dexec.args="scan /Users/you/Movies"

# 生成分类报告
mvn -q exec:java -Dexec.mainClass=com.qian.categorize.Application -Dexec.args="report /Users/you/Movies"

# 指定报告输出位置 / 指定配置文件
mvn -q exec:java -Dexec.mainClass=com.qian.categorize.Application -Dexec.args="report /Users/you/Movies --report /Users/you/report.json"
mvn -q exec:java -Dexec.mainClass=com.qian.categorize.Application -Dexec.args="report /Users/you/Movies --config /Users/you/categorize-config.json"

# 执行移动（人工检查报告后直接执行，无需单独的确认命令）
mvn -q exec:java -Dexec.mainClass=com.qian.categorize.Application -Dexec.args="apply /Users/you/Movies/categorize-report.json"

# 回滚
mvn -q exec:java -Dexec.mainClass=com.qian.categorize.Application -Dexec.args="rollback /Users/you/Movies/categorized/.categorize/manifests/20260915-xxxxxx.json"
```

注意：

- `-Dexec.args=` 后面的子命令和参数整体用引号包住；路径含空格时尤其不能省略引号。
- 必须带 `exec:java` 和 `-Dexec.mainClass=...`。直接写 `mvn "report /路径"` 会报错 `Unknown lifecycle phase "report ..."`，因为 Maven 会把它当成构建阶段而非本工具的子命令。
- 也可以完全绕开 Maven：先 `mvn package`，再用
  `java -cp "target/categorize-jv-1.0.0-SNAPSHOT.jar:$(find ~/.m2 -name 'jackson-databind-*.jar' | head -1):$(find ~/.m2 -name 'jackson-core-*.jar' | head -1):$(find ~/.m2 -name 'jackson-annotations-*.jar' | head -1)" com.qian.categorize.Application report /Users/you/Movies`
  （需要自行拼好 Jackson 依赖的 classpath）。

## 2. 快速上手（核心就两步：report 出报告 → apply 执行）

假设要整理的目录是 `/Users/you/Movies`。

### 第 1 步：生成配置文件

在工作目录（例如就在项目根目录）生成配置骨架：

```bash
categorize "init ."

# 不使用别名时的完整命令：
mvn -q exec:java -Dexec.mainClass=com.qian.categorize.Application -Dexec.args="init ."
```

会生成四个文件：

| 文件 | 作用 |
| --- | --- |
| `categorize-config.json` | 运行设置：分类维度、文件过滤、冲突策略等（通过 `modelFile` 引用下面的模型配置） |
| `model-config.json` | 大模型设置：厂商/接口/模型名/API Key，含中文注释和厂商对照表；新手只填 `apiKey` 一项 |
| `rules.json` | 分类关键词数据：什么关键词归到什么分类 |
| `model-system-prompt.txt` | 可编辑的模型系统提示词；不启用模型时不影响运行 |

> 文件已存在时会自动跳过，不会覆盖你已修改的内容。

### 第 2 步：填写分类规则

打开 `rules.json`，按你的文件情况填写。格式为：

```json
{
  "series": {
    "教父系列": ["教父", "godfather"],
    "指环王系列": ["指环王", "lord of the rings"]
  },
  "actor": {
    "阿尔·帕西诺": ["帕西诺", "pacino"]
  },
  "theme": {
    "科幻": ["科幻", "sci-fi"]
  }
}
```

含义：**维度 → 分类名 → 关键词列表**。文件名中出现任一关键词（不分大小写）即命中该分类。

- 维度名（`series` / `actor` / `theme`）要和 `categorize-config.json` 里的 `dimensions` 对应。
- 关键词可以写中文或英文，建议用文件名里真实出现的词。
- 不会写规则也没关系：可以全部留空 `{}`，改用大模型自动判断（见第 6 节）。

### 第 3 步：试扫描（可选，只看不动）

```bash
categorize "scan /Users/you/Movies"

# 完整命令：
mvn -q exec:java -Dexec.mainClass=com.qian.categorize.Application -Dexec.args="scan /Users/you/Movies"
```

递归列出目录下所有将被处理的文件和数量、总大小。**此命令不修改任何文件**，用来确认过滤设置是否符合预期（隐藏文件、小文件、扩展名等）。

**文件数和资源管理器对不上时**，扫描会额外输出告警，逐类说明差在哪（最多附 5 个样例路径）：

- `[警告] 跳过联接/符号链接目录 N 个……` —— 目录里存在指向其他盘/其他目录的**符号链接或 Windows 目录联接（junction）**（库文件常通过联接挂到大盘）。默认不跟随，防止误入其他盘或绕成环；确认需要扫描时，把 `categorize-config.json` 里的 `"followSymlinks"` 改成 `true` 再扫，程序会按真实路径自动去环，同一目标被多个联接指向时不会重复计数。
- `[警告] 无法访问的文件/目录 N 个（路径过长>260/无权限/被占用）……` —— 这些文件被系统挡住了，按样例路径处理（缩短上层目录名、申请权限、关闭占用程序）后再扫。
- `过滤: 隐藏 x / 忽略名 x / 过小 x / 扩展名 x` —— 被你自己配置的过滤规则挡掉的数量。

### 第 4 步：生成分类报告（关键，不移动文件）

```bash
categorize "report /Users/you/Movies"

# 完整命令：
mvn -q exec:java -Dexec.mainClass=com.qian.categorize.Application -Dexec.args="report /Users/you/Movies"
```

会在被扫描目录下生成三份报告：

- `categorize-report.xlsx` —— **Excel 报告，人工检查主要看它**：「明细」表逐文件列出路径、大小、最终分类、是否低置信度、命中明细（规则还是模型、哪个维度），「分类汇总」表按分类统计文件数和大小，支持筛选排序。
- `categorize-report.json` —— 机器可读，**需要改分类/排除文件时编辑它**（Excel 仅供查看，apply 不读 Excel）。
- `categorize-report.md` —— 人读的 Markdown 报告，含目录树预览、统计、[低置信度] 标记。

此时**没有任何文件被移动**。请打开 Excel 报告逐行检查，重点看「低置信度」标了「是」的行；需要调整就去改 JSON。

如需把报告放到别处：

```bash
categorize "report /Users/you/Movies --report /Users/you/report.json"

# 完整命令：
mvn -q exec:java -Dexec.mainClass=com.qian.categorize.Application -Dexec.args="report /Users/you/Movies --report /Users/you/report.json"
```

### 第 5 步：修正 → 执行（只有两步：report → apply）

**（a）如有分错的，编辑 `categorize-report.json`：**

- 改某个文件的分类：修改该条目的 `"category"` 值（目标文件夹名）。
- 本次不想移动某个文件：把该条目的 `"excluded"` 改为 `true`。

```json
{
  "path": "/Users/you/Movies/教父1.mp4",
  "name": "教父1.mp4",
  "size": 1048576000,
  "category": "教父系列",
  "excluded": false,
  "lowConfidence": false,
  "hits": [ ]
}
```

> 编辑小技巧：常分错的文件，除了改这一次的报告，最好把关键词补进 `rules.json`，以后就能自动分对。

**（b）检查无误后直接执行移动归置（无需单独的确认命令）：**

```bash
categorize "apply /Users/you/Movies/categorize-report.json"

# 完整命令：
mvn -q exec:java -Dexec.mainClass=com.qian.categorize.Application -Dexec.args="apply /Users/you/Movies/categorize-report.json"
```

执行后：

- 文件被移动到 `<输出目录>/<分类名>/` 下（默认输出目录是被整理目录里的 `categorized/`，可在配置中改）。
- 同名文件默认自动改名（如 `教父1 (2).mp4`），**永不静默覆盖**。
- 控制台输出成功 / 跳过 / 失败数量。
- 同时生成**回滚清单**，路径类似：
  `categorized/.categorize/manifests/<批次ID>.json`
  **请妥善保存这个文件**，它是日后还原的依据。

## 3. 回滚（把文件恢复原位）

任何时候想撤销某次归置，拿当时的清单执行：

```bash
categorize "rollback /Users/you/Movies/categorized/.categorize/manifests/20260915-xxxxxx.json"

# 完整命令：
mvn -q exec:java -Dexec.mainClass=com.qian.categorize.Application -Dexec.args="rollback /Users/you/Movies/categorized/.categorize/manifests/20260915-xxxxxx.json"
```

工具会：

1. 逐个把文件移回移动前的原始路径；
2. 移动前用校验和（hash）确认文件没有被你在外部改动过；
3. 输出：还原数 / 校验失败数 / 冲突跳过数 / 其他失败数。

注意：

- **校验失败**说明归置后的文件被改过（或已不是原文件），工具会拒绝还原该文件，需你人工处理。
- 清单是自包含的 JSON，可以复制备份、换电脑、过很久之后再导入还原。
- 回滚要求原路径所在目录仍存在；如原目录已被删除，请先手动建好。

## 4. 配置文件说明（categorize-config.json）

| 配置项 | 含义 | 常用值 |
| --- | --- | --- |
| `dimensions` | 分类维度及**优先级**，越靠前越优先 | `["series","actor","theme"]` |
| `rulesFile` | 规则文件路径（相对于本配置文件） | `rules.json` |
| `outputDir` | 分类后文件存放目录；相对路径相对于被扫描目录 | `categorized` |
| `ignoreHidden` | 忽略以 `.` 开头的隐藏文件/目录 | `true` |
| `followSymlinks` | 是否跟随符号链接/Windows 目录联接（junction）扫描；库通过联接挂其他盘、文件数对不上时改 `true`，自动按真实路径去环 | `false` |
| `ignoreNames` | 按文件名精确忽略 | `[".DS_Store"]` |
| `minSizeBytes` | 小于该大小的文件不处理，`0` = 不限；1MB = 1048576 | `0` |
| `extensionMode` | 扩展名过滤：`OFF` / `WHITELIST`（只处理）/ `BLACKLIST`（不处理） | `OFF` |
| `extensions` | 扩展名列表，大小写不敏感 | `[".mp4",".mkv"]` |
| `conflictStrategy` | 同名冲突：`RENAME` 改名（默认）/ `SKIP` 跳过 / `OVERWRITE` 覆盖（危险） | `RENAME` |
| `cleanEmptyDirs` | 移动后顺手删除变空的原目录 | `false` |
| `lowConfidenceThreshold` | 低于该置信度在报告中标 [低置信度] | `0.7` |
| `modelFile` | 独立模型配置文件（如 `model-config.json`），大模型设置放该文件里由人工维护，详见第 6 节 | `model-config.json`（同目录自动发现） |
| `model` | 大模型内联设置（旧格式，仍兼容；与 `modelFile` 同时存在时以文件为准） | — |

**多维度只取一个分类的规则**：一个文件同时命中多个维度时（例如既属于「教父系列」，主演又是「阿尔·帕西诺」），只按 `dimensions` 中排在最前面的维度归类，其余命中结果保留在报告的 `hits` 明细和 Excel「命中明细」列里。

配置文件的查找顺序：

1. 命令行 `--config <文件>` 指定；
2. 当前工作目录下的 `categorize-config.json`；
3. 当前工作目录 `config/` 子文件夹下的 `categorize-config.json`（exe 绿色包布局）；
4. 都没有则使用内置默认值（此时没有自定义规则）。

附属文件（`modelFile` 指向的模型配置、`rulesFile` 指向的规则文件、
`apiKeyFile`/`systemPromptFile`）写相对路径时，均相对**主配置文件所在目录**解析；
主配置没写 `modelFile` 时，会自动发现同目录下的 `model-config.json`。
`init` 命令和 exe 绿色包释放的是同一套 `config/` 模板（含中文注释）：
`categorize-config.json`、`model-config.json`、`rules.json`、`model-system-prompt.txt`。

示例：

```bash
categorize "report /data/movies --config /data/my-config/categorize-config.json"

# 完整命令：
mvn -q exec:java -Dexec.mainClass=com.qian.categorize.Application -Dexec.args="report /data/movies --config /data/my-config/categorize-config.json"
```

## 5. 文件会被移动到哪里？

默认结构示例（整理 `/Users/you/Movies`）：

```
Movies/
├── categorized/
│   ├── 教父系列/
│   │   ├── 教父1.mp4
│   │   └── 教父2.mp4
│   ├── 指环王系列/
│   │   └── 指环王1.mkv
│   ├── 分类结果-batch-xxxx.xlsx  # 执行结果：原路径/实际移动后路径/状态
│   └── .categorize/
│       └── manifests/            # 回滚清单（重要，别删）
└── （能分类的原文件被移走；未分类的文件仍留在原位置）
```

- 跨磁盘移动会按「复制 → 校验 → 删除原文件」执行，中途失败不会留下半成品。
- **判断不出分类的文件标记为「未分类」，执行时保持原位、不移动**（不再生成「未分类」文件夹），可在报告中人工改分类后再次执行；这些文件仍出现在报告和结果 Excel 中，不会被遗漏。

## 6.（可选）接入大模型自动分类

**开启模型（`model.enabled: true`）后，生成报告时会把扫描到的全部文件名（含各级子目录）一次性交给模型**（超过 80 个自动分批），要求模型先通览全量文件、归纳出共用类目，再逐文件从多个维度给出分类建议——不是逐文件拍脑袋判断，因此不会给单个生活视频造出「婚礼」「美食」这类碎片类目。结果与 `rules.json` 规则按下述方式合并：

- **规则优先**：某个维度只要规则命中了，该维度就以规则为准，模型在同一维度的建议不会覆盖它；
- **AI 多维度补充**：规则没有命中的维度，采用模型的判断。比如规则命中了「教父系列（series）」，模型补充了主演「阿尔·帕西诺（actor）」，两个命中都会保留在报告明细里，最终分类仍按 `dimensions` 优先级取最高维度（上例为 series）；
- 规则和模型都判断不了的文件标记为「未分类」，执行移动时保持原位不动；
- 模型的判断边界由提示词约束：只认影视系列（series）、主演（actor）、题材大类（theme），
  婚礼、美食、聚会、旅行、宝宝成长等私人生活录像不属于影视类目，模型会返回空命中 → 未分类；
  拿不准的文件也宁可留空不猜。若模型仍给出不合意的类目，可在报告里人工改分类或直接编辑
  `config/model-system-prompt.txt` 调整判定口径；
- 模型批量请求/网络失败不会中断报告，该批文件按无模型建议处理。

**推荐方式：编辑独立的 `model-config.json`**（与主配置同目录；exe 绿色包在 `config/` 下）。
主配置通过 `"modelFile": "model-config.json"` 引用它，程序保存主配置时**永远不会重写
这个文件**，所以注释和明文 Key 都不会丢。模板自带六厂商 endpoint/模型对照表和逐项中文
注释，新手只需把 `apiKey` 引号里填上 Key（模板默认就是 DeepSeek + `deepseek-flash` 的 demo）：

```json
{
  "enabled": true,
  "provider": "openai",
  "endpoint": "https://api.deepseek.com/v1/chat/completions",
  "model": "deepseek-flash",
  "apiKey": "sk-在这里填你的Key",
  "apiKeyFile": "",
  "apiKeyEnv": "",
  "systemPromptFile": "model-system-prompt.txt"
}
```

> 兼容旧格式：也可以直接把 `model` 段内联写在 `categorize-config.json` 里；二者同时存在时
> 以 `modelFile` 文件为准。文件支持 `//` 注释（JSONC）。

- `provider` 填的是**接口协议/厂商别名，不是只能填 OpenAI**：
  - OpenAI 兼容协议：填 `openai`，或直接填厂商别名 `火山引擎`/`volcengine`/`ark`/`doubao`/`豆包` 均可（内部都按 OpenAI Chat Completions 协议发请求，实际打到 `endpoint` 指向的厂商服务器）。OpenAI、火山方舟、通义千问、DeepSeek、Kimi、本地 Ollama 等同属此类；
  - `http`：自建的轻量私有服务（请求 `{"name":"文件名"}`，响应 `{"hits":[...]}`）；
  - `none` 或留空：不接模型。填了无法识别的值时，控制台会打印警告且不调用模型。
- **火山方舟配置示例**：`provider` 填 `火山引擎` 或 `openai`；`endpoint` 必须写完整：
  `https://ark.cn-beijing.volces.com/api/v3/chat/completions`；
  `model` 填方舟控制台「在线推理」里的**接入点 ID（`ep-xxxxxxxx`）或模型版本 ID**，不是随意的模型名。
- 密钥三种给法，优先级为 **明文 `apiKey` > `apiKeyFile` 文件 > `apiKeyEnv` 环境变量**（三者只填一个即可）：
  - **直接填 `apiKey`（新手推荐）**：在 `model-config.json` 的 `apiKey` 引号里粘贴 Key。本地 `model-config.json` 已加入 `.gitignore`（模板 `src/main/resources/templates/model-config.json` 是无 Key 的空白 demo，照常入库），**不会误提交 git、不会打进 jar**；但切勿手动把填了 Key 的文件发给别人。
  - **密钥文件**：把密钥单独放一个本地文件（如配置旁的 `model-api-key.txt`，文件里只写密钥一行，支持 `#` 注释和空行），`model-config.json` 里写 `"apiKeyFile": "model-api-key.txt"`、`apiKey` 留空。相对路径相对于模型配置文件所在目录，也可写绝对路径。
  - 环境变量：留空 `apiKey`/`apiKeyFile`，填 `"apiKeyEnv": "CATEGORIZE_MODEL_API_KEY"`，执行前 `export CATEGORIZE_MODEL_API_KEY="sk-xxxx"`。
- **自定义系统提示词**：`config/model-system-prompt.txt`（init 时释放到配置同目录）即模型 system 消息，可随时用文本编辑器修改，无需改代码、重新打包。`model-config.json` 中通过 `systemPromptFile` 指定（默认就是该文件）：
  ```json
  "systemPromptFile": "model-system-prompt.txt"
  ```
  相对路径相对于模型配置文件所在目录，也可写绝对路径；设为 `""` 则使用程序内置提示词。运行时读取的是外部文件，不会把你的自定义内容打进 jar。文件里的 `{dimensions}` 会在运行时替换为配置的维度列表。注意：为保证返回结果能被程序解析，自定义提示词仍必须要求模型只返回 `{"results":[{"index":1,"hits":[{"dimension":"...","category":"..."}]}]}` 这种按输入编号逐文件对应的 JSON（`hits` 为空数组表示该文件无法归类）。
- 本地 Ollama 示例：`endpoint` 填 `http://localhost:11434/v1/chat/completions`，密钥留空，`model` 填本地模型名（如 `llama3`）。
- 同一次生成报告中模型只按批次调用（每批最多 80 个文件名，温度为 0），N 个文件从原来的 N 次请求降为约 N/80 次，省钱省时；规则命中的文件也会出现在批次中，但合并时规则优先。重新执行 `report` 会重新调用。

不接模型也完全能用：`enabled: false` 时纯靠 `rules.json` 判断，判不出的标记为「未分类」、执行时保持原位。

## 7. 命令速查表

| 命令 | 作用 | 是否改动文件 |
| --- | --- | --- |
| `init [dir]` | 生成配置、规则、模型提示词模板 | 仅新建模板文件 |
| `scan <dir> [--config f]` | 递归扫描，列出待处理文件 | 否 |
| `report <dir> [--config f] [--report json]` | 生成 Excel + JSON + Markdown 分类报告 | 否 |
| `apply <report.json> [--config f]` | 人工检查/编辑报告后执行移动，生成回滚清单 | **是（移动文件）** |
| `rollback <manifest.json> [--config f]` | 按清单还原到原路径 | **是（移回文件）** |

典型完整流程：

```
init（仅首次）→ （编辑 rules.json）→ scan（可选）→ report
                                                      ↓
                              人工检查 Excel，需要调整就改 report.json
                                                      ↓
                                                    apply
                                                      ↓
                                          出问题随时 rollback
```

## 8. 常见问题

**Q：生成报告后我的文件被移动了吗？**
没有。`report` 只生成 Excel/JSON/Markdown 三份报告，只有 `apply` 才会移动文件。

**Q：`apply` 之后还能撤销吗？**
能。只要保留着 `categorized/.categorize/manifests/` 下的清单 JSON，随时可以 `rollback`。建议每次归置后把清单另存一份。

**Q：报告里某些文件分类明显错了怎么办？**
在 `categorize-report.json` 里改 `category`（或设 `"excluded": true` 跳过），然后直接 `apply`（Excel 仅供查看，不能作为编辑入口）；再把正确关键词补进 `rules.json`，避免下次再错。

**Q：目标文件夹里已经有同名文件会怎样？**
默认 `RENAME`：自动改名为 `xxx (2).ext`，绝不覆盖。也可在配置里改成 `SKIP` 或 `OVERWRITE`。

**Q：执行到一半失败了怎么办？**
查看控制台的失败清单；已移动的文件都有清单记录，可直接 `rollback` 全部还原后修正问题重来，或排除问题文件后对剩余文件重新生成报告再执行。

**Q：配置文件应该放在哪？**
放在运行命令时的当前目录即可自动识别（也支持当前目录的 `config/` 子文件夹，exe 绿色包即此布局）；或用 `--config /路径/categorize-config.json` 显式指定。`model-config.json`、`rules.json` 等附属文件的相对路径都相对于主配置文件所在目录；`model-config.json` 即使不在主配置里显式写 `modelFile`，只要和主配置同目录也会自动发现。

**Q：执行 `categorize "report ..."` 报 `Unknown lifecycle phase "report ..."`？**
说明 `categorize` 别名没有正确生效，命令被直接交给了 Maven（等价于执行 `mvn "report ..."`）。请确认别名是在**当前终端窗口**里用第 1 节那条完整 `alias` 命令设置的（`alias categorize='mvn -q exec:java ...'`，必须包含 `exec:java`）；或者干脆不用别名，按第 1 节「不设别名」里的完整 `mvn -q exec:java -Dexec.mainClass=... -Dexec.args="report ..."` 写法执行。

**Q：如何只整理视频文件？**
把 `extensionMode` 设为 `WHITELIST`，`extensions` 填上 `[".mp4",".mkv",".avi",".mov"]`。
