# 文件自动分类归置工具 需求文档 v1

| 项 | 内容 |
|---|---|
| 版本 | v1 |
| 日期 | 2026-09-12 |
| 项目 | categorize-jv（Maven / JDK 8，根包 `com.qian.categorize`） |

---

## 1. 背景与目标

用户本地（尤其是影视、资料类）文件数量庞大、命名杂乱，手动按系列、主演、主题等维度整理耗时且容易遗漏。

本工具接收一个本地目录路径，递归扫描其中全部文件，**动态归纳**出分类并对文件进行多维度归置。核心原则：

1. **安全第一**：任何文件变更前必须先出报告，经用户确认后才执行；
2. **可回滚**：每次移动都有完整记录，随时可把文件还原到原路径；
3. **分类智能化**：本地规则无法判断时，可借助私有化模型或外部大模型完成分类。

## 2. 名词定义

| 名词 | 含义 |
|---|---|
| 维度 | 分类的角度，如：系列、主演、主题、类型、年份等 |
| 分类（类别） | 某一维度下动态归纳出的具体值，如主演维度下的「阿尔·帕西诺」 |
| 维度优先级 | 各分类维度的排列顺序；一个文件命中多个分类时，取优先级最高的一个作为最终分类 |
| ~~索引~~ | v1 暂不实现多维度索引：每个文件最终只归入一个分类文件夹 |
| 报告 | 扫描分类后、移动前产出的「文件 → 目标位置」映射清单 |
| 操作清单（manifest） | 执行移动时落盘的完整变更记录，是回滚的依据 |

## 3. 范围

**v1 包含：**

- 目录递归扫描与过滤
- 多维度动态分类（规则 + 元数据 + 模型三层）
- 报告生成、人工确认与修正
- 文件移动归置（按维度优先级取唯一分类，直接移动）
- 操作清单与回滚
- CLI 工作流与配置文件

**v1 不包含（后续版本）：**

- **多维度索引（详见第 4 节，本次明确不做）**
- 图形界面（GUI）
- 实时监控目录、自动增量整理
- 网络/网盘文件处理
- 多用户与权限体系

## 4. 【后续版本预留】多维度索引 —— 本次 v1 明确不需要！

> **⚠️ 注意：多维度索引功能本次 v1 不实现，不要开发、不要预留多余代码，仅在此记录为后续版本的设计方向。**

**设想（仅供未来参考，本次不做）：**

- 一个文件同时归属多个维度（如既属某系列、主演又是某演员）时，物理文件只按一个主维度移动，其他维度的分类文件夹中放索引（快捷方式 / 索引清单）而非副本。
- 配套需要：主维度选择、索引文件格式、索引生成与清理、回滚时删除索引等。

**本次 v1 的实际做法：**

- 每个文件在识别过程中可命中多个分类，但最终**按配置的维度优先级只取一个分类**，直接移动到该分类文件夹。
- **不生成任何索引文件、不建快捷方式、不复制副本。**
- 未被选中的其他命中结果仅保留在报告明细中作为参考信息。

## 5. 总体流程

```
用户输入路径
     │
     ▼
 [scan] 递归扫描 → 文件清单（可缓存）
     │
     ▼
 [report] 分层分类（规则→元数据→模型）→ 分类报告（JSON + Markdown）
     │
     ▼
 [confirm] 用户审阅/编辑报告（改分类、排除文件）  ◄── 低置信度重点复核
     │
   用户确认
     ▼
 [apply] 生成操作清单 → 执行移动（唯一分类，不建索引） → 结果报告
     │
     ▼（随时）
 [rollback] 导入清单 → 校验 → 还原到原始路径
```

**报告未确认前，不允许产生任何文件移动。**

## 6. 功能需求

### F1 目录扫描

| 编号 | 需求 |
|---|---|
| F1-1 | 入参为一个本地目录绝对路径 |
| F1-2 | 递归扫描该目录下所有文件与全部层级子目录 |
| F1-3 | 支持扩展名白名单 / 黑名单过滤 |
| F1-4 | 默认忽略隐藏文件与系统垃圾（如 `.DS_Store`），可配置 |
| F1-5 | 支持按文件大小阈值过滤 |
| F1-6 | 不跟随符号链接，防止目录环路 |
| F1-7 | 输出扫描统计：文件数、总大小、耗时 |
| F1-8 | 扫描结果可缓存，供报告阶段复用，避免重复扫描 |

### F2 多维度分类

| 编号 | 需求 |
|---|---|
| F2-1 | 支持多个分类维度（系列、主演、主题等），维度可在配置中增减 |
| F2-2 | 分类种类必须由本次扫描到的**全部文件动态归纳**得出，不预先写死 |
| F2-3 | 分层识别，按优先级依次尝试：① 历史修正规则 → ② 文件名/路径规则 → ③ 本地元数据解析 → ④ 模型 |
| F2-4 | 前序层级已确定结果的，不再调用后续层级（尤其模型），以控制成本 |
| F2-5 | 支持调用私有化部署模型或外部大模型 API；通过统一接口适配，配置可切换 |
| F2-6 | 模型密钥等敏感信息只放配置文件/环境变量，不写死在代码中，不进入操作清单 |
| F2-7 | 模型分类结果按文件标识缓存，同一文件不重复请求 |
| F2-8 | 分类结果带置信度；低置信度项在报告中显式标注 |
| F2-9 | 一个文件在识别过程中可能命中多个维度的多个分类；**最终归类按维度优先级只取一个**（维度优先级在配置中定义），未被选中的命中结果保留在报告明细中供参考 |

### F3 报告与确认

| 编号 | 需求 |
|---|---|
| F3-1 | 扫描分类后先生成报告，不做任何文件变更 |
| F3-2 | 报告提供两种形式：**JSON**（机器可读，可编辑，作为确认与回滚输入）和 **Markdown/HTML**（人工阅读） |
| F3-3 | 可读报告包含：目标目录树预览、每个分类下的文件数与总大小、低置信度标记 |
| F3-4 | 用户确认前可编辑报告：修改文件的目标分类、排除文件 |
| F3-5 | 用户的人工修正可沉淀为规则，在后续执行中优先命中（F2-3 第①层） |
| F3-6 | 只有用户明确确认报告后，才允许执行移动 |

### F4 移动归置

| 编号 | 需求 |
|---|---|
| F4-1 | 默认操作方式为**直接移动** |
| F4-2 | 文件按最终分类（按维度优先级取的唯一结果）物理移动到对应分类文件夹 |
| F4-3 | v1 不生成多维度索引，每个文件在分类结果中只有一个目标位置（多维度索引为后续版本预留） |
| F4-4 | 目标已存在同名文件时按冲突策略处理，默认策略为**自动重命名**（如 `片名 (2).mp4`），可选跳过/覆盖；**默认策略下永不静默覆盖** |
| F4-5 | 跨磁盘移动按「复制 → 校验一致 → 删除原文件」执行，任一步失败不留半成品 |
| F4-6 | 每批执行生成唯一**批次 ID** |
| F4-7 | 执行中途失败后支持从断点续做（同批次重试不重复处理已完成项） |
| F4-8 | 执行完成后输出结果报告：成功 / 跳过 / 失败文件清单及原因 |
| F4-9 | 支持移动完成后清理空目录（可配置开关） |

### F5 操作清单与回滚

| 编号 | 需求 |
|---|---|
| F5-1 | 每次执行移动**之前**必须先生成并落盘操作清单（manifest，JSON） |
| F5-2 | 清单内容至少包含：批次 ID、时间戳、原路径、目标路径、文件大小、校验和（hash） |
| F5-3 | 清单自包含、可长期保存；用户可事后导入任意一份清单执行回滚 |
| F5-4 | 回滚动作：把文件从当前位置移回原路径 |
| F5-5 | 回滚前用校验和校验文件是否被外部篡改，校验失败的文件单独列出并中止该项还原，不影响其他文件 |
| F5-6 | 支持按批次 ID 或导入清单文件选择回滚范围 |
| F5-7 | 回滚同样遵循同名冲突策略，并输出回滚结果报告 |

### F6 配置与可观测

| 编号 | 需求 |
|---|---|
| F6-1 | 配置分两文件：**设置文件**（分类维度及维度优先级、模型接口与密钥、忽略规则、冲突策略、大小阈值、是否清理空目录）和**独立规则文件**（分类关键词数据，通过 `rulesFile` 引用）；规则数据与运行设置分离，便于后续程序自动沉淀人工修正 |
| F6-2 | 提供 CLI 子命令：`scan`、`report`、`confirm`、`apply`、`rollback` |
| F6-3 | 全程写操作日志（扫描、分类、移动、回滚），便于审计 |
| F6-4 | 关键危险操作（移动、删除、回滚）在日志中可追溯到批次 ID |

## 7. CLI 命令一览（初步定义）

```
categorize init     [dir]                       # 生成 categorize-config.json + rules.json 骨架
categorize scan     <dir>                       # 扫描，输出/缓存文件清单
categorize report   <dir> [--config <file>]     # 生成分类报告
categorize confirm  <report.json>               # 编辑/校验报告（交互式或指定编辑后的文件）
categorize apply    <report.json>               # 确认后执行，落盘 manifest
categorize rollback <manifest.json>             # 按清单回滚
```

配置查找顺序：`--config` 参数 → 当前工作目录的 `categorize-config.json` → 内置默认值。

## 8. 非功能需求

| 类别 | 要求 |
|---|---|
| 运行环境 | JDK 8，Maven 构建；macOS / Windows 均可运行（路径与换行需跨平台处理） |
| 安全 | 默认不覆盖文件；密钥不落日志、不入清单；不跟随符号链接 |
| 性能 | 大目录扫描支持缓存；模型调用有缓存与批量能力，控制调用成本 |
| 可靠 | 文件操作具备失败恢复能力；任何成功执行的 `apply` 都必须存在对应可回滚清单 |
| 可测试 | 核心逻辑（扫描过滤、分类映射、清单生成/回滚）具备单元测试，文件系统操作使用临时目录测试 |

## 9. 约束与依赖

- Java 8 语法，新增第三方依赖必须兼容 JDK 8。
- 模型能力依赖外部服务（私有化或公有 API），需在无网络/无模型可用时仍能完成规则层分类，模型层失败的文件标记为「未分类/待人工处理」，不阻塞整体流程。

## 10. 验收标准（关键场景）

1. 给定含多层子目录、多类文件的目录，工具能递归扫出全部非忽略文件并给出正确统计。
2. 报告中每个文件都有唯一的目标分类；同时命中多个分类的文件按配置的维度优先级取最高者，不产生索引或副本。
3. 未确认报告时，目标目录不发生任何变化。
4. 确认执行后，文件位于报告所示位置；同批次 manifest 可查、含 hash。
5. 导入该 manifest 执行回滚，全部文件还原到原路径，目录恢复执行前状态。
6. 目标位置同名冲突时默认产生重命名文件，不出现原文件被覆盖的情况。
7. 模型不可用时流程仍可完成，失败项明确列出。
